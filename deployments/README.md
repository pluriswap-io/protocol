# deployments

Address records, written by the deploy scripts and read by the ones that follow them. Not secrets,
not a source of truth about the code: a record only says *where* something was put, never that it
still matches what `src/` says today. To ask that, run the doctor:

```shell
forge script script/Doctor.s.sol:Doctor --rpc-url $RPC
```

## What is tracked

- `sepolia*.json` — Arbitrum Sepolia. Regenerated by `script/e2e.sh` with `RPC_URL` + `DEPLOY_KEY`.
- `31337*.json` — anvil. **Gitignored**: a throwaway chain, rewritten on every local `e2e.sh` run.

## The current testnet records

`sepolia*.json` are the Arbitrum Sepolia deploy of 2026-10-24, the first one made with the whole chain in
one `e2e.sh` run: 13 scripts, the on-chain checks and the doctor (77 checks, 0 failures). The previous
stack was deleted on 2026-09-23 because it had drifted (seven doctor failures); git keeps it if anyone
needs to look back.

`sepolia-private.json` was redeployed on 2026-10-26 with the tagged identity commitment (LABS-252); the doctor
passes (77 checks, 0 failures). `sepolia-private-deal.json` is a private deal on that stack, made by `script/js/private-deal.ts` with proofs
generated against the live trees: two enrolled and registered accounts, a bond deposit each, one bonded
activation of one lot, a Peaceful terminal, both claims (credited) and both reabsorbs. Its holder account is
what a restore from the recovery phrase and the chain is tested against.

## Shape

One file per deploy script, keyed by chain. A packaged stack records its own escrow, so more than one
escrow can exist on a chain at a time (core-only vs packaged vs private): a pool must be pointed at
the escrow whose EIP-712 domain its `HolderAuthorization`s were signed against. Do not mix ABIs
across records.

Testnet package deploys use placeholders (`feeRecipient 0xFEE`, `sink 0xdeaD`, `TRIBUNAL 0x71B`).
Those are never a production identity.
